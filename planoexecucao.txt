PLANO DE EXECUÇÃO - FINDY
Atualizado em 16/11/2026. Resumo em passos; histórico anterior disponível no Git.

OBJETIVO
MVP para encontrar profissionais e solicitar serviços diretamente.
Tecnologias: HTML/CSS/JavaScript, Java 21, Spring Boot, Maven e PostgreSQL.
Uma conta pode contratar e oferecer serviços; ADMIN analisa os profissionais.
IMPLEMENTADO indica código existente; não substitui conferência visual ou online.

COMO ABRIR NESTE COMPUTADOR JÁ CONFIGURADO
1. Abrir Docker Desktop e aguardar iniciar.
2. Na raiz: docker compose up -d --wait
3. Iniciar: .\backend\plataformaservicos\start-local.ps1
4. Aguardar Started e abrir http://localhost:8080/index.html.
5. Para carregar alterações: Ctrl+C no backend, iniciar novamente e Ctrl+F5.
6. Encerrar: Ctrl+C no backend; docker compose stop.
Não recriar tabelas, substituir .env nem apagar o volume no uso diário.
Não iniciar o container manual antigo findy-postgres junto do Compose.
Live Server não é necessário; na porta 5501 ele depende da API local na 8080.

AMBIENTES E DADOS
- Desenvolvimento: banco findy no Docker local, localhost:5433.
- Testes: findy_cadastro_test_20261028 no mesmo PostgreSQL local, separado.
- Produção: aplicação no Render e banco PostgreSQL no Neon.
- Site registrado: https://site-findy.onrender.com/index.html.
- O site público não exige Docker no computador de quem visita.
- Git envia código e scripts; dados dos bancos não são sincronizados pelo push.
- Não publicar .env, credenciais, tokens ou senhas nos documentos.
- Fotos enviadas ficam no PostgreSQL; imagens estáticas em frontend/pages/images.

PASSO 2 - CONTAS E ACESSO [IMPLEMENTADO]
Cadastro, login/logout, sessão e senhas protegidas por BCrypt.
Dados pessoais e upload de foto JPG/PNG; separação USUARIO/ADMIN.
Recuperação por link temporário: Brevo envia e-mail, Findy redefine a senha.
Link válido por 30 minutos, uso único; senha alterada invalida sessões antigas.
Envio exige BREVO_API_KEY, EMAIL_FROM e APP_URL configurados no ambiente.

PASSO 3 - CADASTRO PROFISSIONAL [IMPLEMENTADO EM 28/10]
Três etapas: Sobre você, Seu trabalho e Revisão.
Habilidades em sete categorias, opção iniciante e prévia pública.
Para enviar: foto, telefone com DDD, bairro, cidade e UF completos.
Admin aprova, solicita correção ou recusa definitivamente, com histórico.
Recusa definitiva bloqueia reenvio do perfil, preservando a conta de cliente.
SQL: database/cadastro_profissional.sql. Guia: CADASTRO_PROFISSIONAL.md.

PASSO 4 - SERVIÇOS E BUSCA [IMPLEMENTADO]
Prestador cadastra ofertas, categoria, unidade e faixa opcional de preço.
Perfil/conta ativos, aprovação e serviço ativo são necessários para publicação.
Habilidade não cria oferta automaticamente; categoria vem do serviço.
Busca e paginação retornam um profissional, mesmo com várias ofertas na categoria.
Perfis fictícios são identificados; não remover dados reais ao limpar exemplos.

PASSO 5 - PEDIDOS REAIS [IMPLEMENTADO EM 30/10]
Cliente escolhe serviço, data futura, quantidade, região/endereço e mensagem.
Faixa de preço é referência: valor final, escopo e pagamento são negociados.
Não há cobrança, comissão, mensalidade ou confirmação bilateral de preço no sistema.
Prestador aceita/recusa; cliente cancela antes do horário, pendente ou aceito.
Somente participantes acessam o pedido; admin externo também não tem acesso.
Aceite exige horário futuro e serviço/perfil disponíveis; alterações são transacionais.
SQL: database/contratacao_real.sql. Regras/API: CONTRATACAO_REAL.md.

OUTRO COMPUTADOR / BANCO NOVO
Git, JDK 21 e Docker Desktop; obter branch combinada, criar .env próprio.
Criar volume findy_postgres_data; iniciar Compose conforme database/README.md.
Em banco NOVO E VAZIO, executar uma vez nesta ordem:
usuario_e_prestadores.sql, categorias.sql, servicos.sql, solicitacoes.sql,
avaliacoes.sql, recuperacao_senha.sql, fotos_usuarios.sql,
cadastro_profissional.sql e contratacao_real.sql (todos em database/).
Não repetir scripts antigos de criação sobre banco existente ou Neon.
Banco existente: aplicar somente incrementos faltantes; exemplos são opcionais.
Uma nova instalação não recebe automaticamente contas do seu Docker ou Neon.
Colega pela internet: usar link do Render; acesso às tabelas exige permissão separada.
Na mesma rede: pode usar http://IP-DO-SEU-PC:8080, com backend ativo e rede permitida.
Não expor a porta do PostgreSQL; localhost aponta para o computador de quem acessa.
