PLANO DE EXECUÇÃO - FINDY

OBJETIVO
Transformar o protótipo em uma plataforma real para contratar e oferecer serviços,
reutilizando o visual atual e substituindo dados fixos por informações do banco.

ESTADO ATUAL
- Frontend HTML/CSS/JavaScript com sete telas: início, login/cadastro, categorias,
  perfis de contratante/prestador, contratação e status do atendimento.
- Logo, imagens, estilos e interações de demonstração já existem.
- Profissionais e perfis são exemplos fixos; status/avaliações usam localStorage.
- Backend Spring Boot/Maven, Java 21, com JPA, Validation e driver PostgreSQL.
- PostgreSQL no Docker e conexão com Spring Boot configurados e testados.
- Ainda faltam tabelas, API própria, autenticação e integração das telas.

DECISÕES TOMADAS
- Uma única conta permite contratar e também oferecer serviços.
- Dados pessoais ficam em USUARIOS; perfil profissional opcional em PRESTADORES.
- Pessoas preenchem e editam seus próprios dados e fotos.
- Começar com um administrador para editar, aprovar/recusar e desativar cadastros.
- Login único: backend identifica USUARIO ou ADMIN e libera as funções permitidas.
- Exemplos atuais serão dados de demonstração no banco, acessados por ID.

PRIMEIRA ENTREGA - ORDEM DE EXECUÇÃO
1. Definir aprovação e dados obrigatórios; criar modelo, migrations e tabelas.
2. Implementar cadastro, login/logout, hash de senha e autorização no backend.
3. Criar Minha Conta e formulário para ativar/editar o perfil profissional.
4. Criar administrador inicial por configuração segura e painel de cadastros.
5. Implementar PENDENTE/APROVADO/RECUSADO, motivo, responsável/data e reenvio.
6. Integrar telas com a API: perfis por ID, dados persistentes e publicação autorizada.
7. Migrar exemplos e testar login, edição, aprovação e bloqueio de acesso indevido.

MODELO DO BANCO PROPOSTO
- USUARIOS: identificação, contato, localização, foto, senha_hash, papel e ativo.
- PRESTADORES: usuario_id único, descrição, experiência e região de atendimento.
- CATEGORIAS e SERVICOS: categoria, prestador, descrição, preço e unidade de cobrança.
- SOLICITACOES: cliente, serviço, status, agendamento, endereço e valores acordados.
- AVALIACOES: solicitação, participantes, nota 1 a 5 e comentário; uma por solicitação.
- Aprovação fica no cadastro escolhido para análise, separada de papel e ativo.

ENTREGAS SEGUINTES
- Cadastro de serviços, busca/filtros e painel do prestador.
- Solicitação, aceite/recusa, agendamento, conclusão, avaliação e histórico.
- Recuperação de senha, revisão de responsividade, testes, documentação e publicação.

DÚVIDAS PARA DISCUTIR COM O GPT
- Aprovar todas as contas ou apenas perfis de prestadores?
  Sugestão: permitir login/edição e exigir aprovação para publicar e oferecer serviços.
- Login por e-mail ou também telefone?
- Contratação direta ou orçamento? Preço por hora/diária e qual regra de taxa?
- Como confirmar conclusão, liberar avaliação e tratar contestação?
- Mudanças no perfil aprovado precisam de nova análise?
- Chat entre usuários, pagamento online, portfólio e agenda real entram em qual etapa?
  Hoje o chat é FAQ, pagamento é seleção visual e Google Agenda é link de criação de evento.

CRITÉRIO DA PRIMEIRA ENTREGA
Usuário cria conta, entra, salva dados, solicita ativação profissional e acompanha
aprovação. Administrador gerencia cadastros. Perfil aprovado exibe dados do banco.
Usuários comuns só editam seus dados; permissões são verificadas no servidor.
Dados de demonstração ficam identificados, sem notas/históricos fictícios em contas reais.

TUTORIAL - ABRIR O PROJETO NESTA MÁQUINA (WINDOWS/POWERSHELL)
Não é preciso reinstalar nem recriar o banco a cada vez. Apenas iniciar o que
estiver parado. Para ver somente as telas de exemplo, basta abrir o frontend.

1. Abra o Docker Desktop e espere o motor terminar de iniciar.
2. Abra a pasta SITE_FINDY no VS Code e um terminal PowerShell na raiz
   (a pasta que contém compose.yaml e planoexecucao.txt).
3. Inicie/confira o banco:
   docker compose up -d --wait
   docker compose ps
   O serviço postgres deve aparecer como healthy. Se já estiver rodando,
   o comando reaproveita o banco; não recria seus dados.
4. No mesmo terminal, inicie o backend:
   .\backend\plataformaservicos\start-local.ps1
   O script lê o .env e executa o Maven. Deixe esse terminal aberto.
   Aguarde "Started PlataformaservicosApplication"; o backend usa a porta 8080.
   localhost:8080 pode retornar 404, pois ainda não há rotas próprias.
5. Para ver o site, abra frontend/pages/index.html no navegador pelo Explorador
   de Arquivos. Se usar a extensão Live Server do VS Code, clique com o botão
   direito no index.html e escolha "Open with Live Server".
   As telas ainda são protótipos: iniciar o backend não torna o login funcional.

AO TERMINAR
- Ctrl+C no terminal do backend para encerrá-lo.
- Para parar o banco, execute na raiz:
  docker compose stop
- Os dados permanecem no volume. Não inicie o container manual antigo
  findy-postgres junto com o Compose: ambos usam o mesmo armazenamento.

TUTORIAL - PRIMEIRA VEZ EM OUTRA MÁQUINA (WINDOWS)
1. Instale Git, JDK 21, Docker Desktop e VS Code. Abra o Docker Desktop.
   Confira no PowerShell: java -version e docker info (Client e Server sem erro).
2. Leve a versão atual do projeto para a outra máquina.
   Se usar GitHub, as mudanças locais precisam ser commitadas e enviadas antes;
   os arquivos de configuração recém-criados ainda estão pendentes no Git.
   Para baixar a versão publicada:
   git clone https://github.com/otaviograu1654/SITE-FINDY.git SITE_FINDY
   cd SITE_FINDY
   Abra essa pasta no VS Code. Também é possível transferir os arquivos diretamente.
3. Na raiz, prepare a configuração local (somente se ainda não existir .env):
   Copy-Item .env.example .env
   Abra o .env e substitua POSTGRES_PASSWORD pela senha local desejada.
   Mantenha POSTGRES_DB=findy, POSTGRES_USER=postgres, POSTGRES_PORT=5433
   e POSTGRES_VOLUME=findy_postgres_data para seguir estes comandos.
   O .env não vai para o Git. Não copie o nome de volume específico desta máquina.
4. Crie o volume externo, necessário somente na preparação inicial:
   docker volume create findy_postgres_data
5. Execute os passos 3 a 5 do tutorial acima para iniciar banco, backend e telas.
   Na primeira vez, é necessária internet para baixar a imagem e dependências.
   Não precisa instalar Maven separado: o projeto possui Maven Wrapper.
6. Nas próximas vezes, siga apenas o tutorial de abertura normal.

IMPORTANTE SOBRE OUTRA MÁQUINA
- O banco novo começa vazio; Git/cópia do projeto não transfere o volume Docker.
  Para levar dados existentes, será necessário fazer backup e restaurar o banco.
- Em banco já criado, mudar a senha no .env não altera a senha no PostgreSQL.
- Se a porta 5433 estiver ocupada, escolha outra em POSTGRES_PORT no .env;
  Compose e script do backend usam essa configuração.
